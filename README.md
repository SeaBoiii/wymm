# Living Memory Garden

A mobile-first, garden-themed proposal made for Nurulain by Aleem. The site is
plain semantic HTML, CSS, and progressively enhanced JavaScript, generated by a
small Node build and published through GitHub Pages.

The deployed URL is deliberately marked `noindex`, but GitHub Pages is still
public hosting. Anyone with the URL may be able to open it.

If the repository or domain changes, update `metadata.canonicalUrl` in
`content.mjs` so the spoiler-safe social image keeps an absolute share-preview
address.

## Personalise before sharing

[`content.mjs`](content.mjs) is the only editable story source. It contains:

- names, neutral social metadata, the proposal date, and the final note;
- the letter;
- exactly five memories, each with a title, date, place, story, media path,
  alternative text, caption, and botanical motif;
- evidence-based reasons and three concrete promises;
- proposal, celebration, and spoiler-safe keepsake wording.

The supplied memories are honest editorial placeholders because private dates,
places, and approved photos were not provided. Search `content.mjs` for
`PERSONALISE` and replace all five memories with true details before publishing.
The build prints the same five reminders. Remove each completed memory's
`editorNote`; `npm run check:release` and the deployment workflow refuse to
publish while any reminder remains.

Each default memory points to a symbolic illustration in `assets/keepsakes/`.
To use a personal photo:

1. Keep the original outside this repository and `assets/`. Export an approved,
   resized derivative with EXIF/GPS metadata removed under `assets/`.
2. Change that memory's `media` path.
3. Replace `alt` with a useful description of what the image contributes. Avoid
   repeating the caption.
4. Keep the caption short and specific to the memory.

If a media file is missing, the build deliberately renders a coordinated
botanical fallback rather than emitting a broken image request.
Only assets referenced by the rendered page are copied into `dist/`; source
masters and unused files are not published.

Do not edit `index.html` by hand. It is a generated root preview; `dist/` is the
deployment artifact.

## Build and preview

Node 20 or newer is required.

```powershell
npm ci
npx playwright install chromium webkit
npm run check
npm test
npm run build
npm run preview
```

Then visit `http://127.0.0.1:4173`.

`npm run check` validates required fields, the five-memory and three-promise
structure, `noindex`, the proposal date format, and the 650–900 word narrative
budget. `npm run check:release` additionally rejects unfinished personalisation
notes. `npm run build` escapes all editable values, pre-renders the complete
story, and copies only referenced runtime files into `dist/`. The story remains
readable without JavaScript; JavaScript handles motion and proposal-state
enhancements only.

Responsive AVIF/WebP sources are used automatically when all candidates named
in `content.mjs` exist, with metadata-free optimised JPEG fallbacks. Only the
hero artwork and its title font are preloaded; the proposal scene and memory
media are lazy loaded. Browser flows are tested in both Chromium and WebKit.

## Publish with GitHub Pages

1. Push to the `main` branch and let its validation run finish.
2. Review the local preview at every required viewport, including the social
   preview and all private copy.
3. In **Settings → Pages**, choose **GitHub Actions** as the source.
4. Manually run **Validate, build, and deploy GitHub Pages** on `main`, checking
   the private-content review confirmation.

Pull requests and pushes validate content, run tests, and build without
deploying. Only the confirmed manual run uploads `dist/` and deploys that
validated artifact. No answer is sent, tracked, or published by the site.
